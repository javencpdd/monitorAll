# 03 前端框架与布局（Vue3 / grid-layout-plus / CSS）

## 3.1 ⭐ 变量名与组件标签撞车 —— 静默吞掉整棵子树

**现象**：DB 里有 8 张卡、控制台**无任何报错**，但画布全黑；WS 日志 `channels=0`（CardHost 从未挂载）；
诊断角标显示 `卡片=8张` 而 `DOM: 项数=0`。

**根因**：Vue 模板编译器解析带连字符标签时依次尝试 `grid-layout` → **`gridLayout`（驼峰）** → `GridLayout`。
我在 `<script setup>` 里引入了 `const gridLayout = ref<Layout>(...)`，**驼峰名与标签名完全一致** →
`<grid-layout>` 被解析成这个数组 ref 而不是导入的组件，拿数组当组件渲染时整棵子树被静默吞掉。

**修复**：把局部变量重命名为 `layoutRef`（`sed -i 's/\bgridLayout\b/layoutRef/g'`），**1 处改名解决**。

**⭐ 通用教训**：`<script setup>` 里**禁止用与组件标签驼峰名同名的变量**——
用了 `<grid-layout>` 就不要有 `gridLayout`，用了 `<grid-item>` 就不要有 `gridItem`，`<card-host>` 同理。
开发模式可能只是警告，**生产构建下会静默吞掉整棵子树且控制台无报错**，极难排查。

## 3.2 grid-layout-plus 不内置任何 CSS（resize 失效）

**现象**：动态新增的卡片无法拖拽 resize / 改尺寸。

**根因**：`grid-layout-plus@1.1.1` **不内置 CSS 文件**，`grid-item` 渲染的 `.vgl-item__resizer` 手柄定位全靠宿主。
`DashboardCanvas.vue` 里该 class 只写了 `right/bottom` 却**缺 `position: absolute`**（`.vgl-item` 也缺 `position: relative`）。

**修复**：
```css
:deep(.vgl-item)            { position: relative; }
:deep(.vgl-item__resizer)   { position: absolute; z-index: 3; }
```
并给 `<grid-item>` **显式**传 `:is-draggable="editMode" :is-resizable="editMode"`（不依赖从父级继承的时序）。

**教训**：引入"不内置样式"的库，必须自查它内部生成的 class 的定位样式是否补全。

## 3.3 回环卡死浏览器（添加卡片 / 拖拽瞬间卡死）

**现象**：点「添加到看板」瞬间浏览器卡死；拖拽看板也卡死。

**根因（源自库源码）**：`GridLayout` 内部 `watch(() => [f.layout, f.layout.length])` → `Ee()`（layoutUpdate），
**末尾固定 `emit("layout-updated")`**。此前 `onLayoutUpdated` 无条件调 `saveLayoutNow` →
`board.cards = board.cards.map(...)` 每次生成全新数组 → `layout` computed 新引用 → `:layout` prop 变化 →
再次 emit → 无限「保存→重渲染→再 emit」，每圈还带一次 POST。

**修复（双保险）**：
1. `isLayoutChanged(next)` 比对，坐标未变直接 return，不回写；
2. `saveLayoutNow` 开头对「patch 与现有布局完全一致」短路返回，不替换 cards 数组。

**⭐ 通用教训**：凡是「派生值回传给第三方组件 + 组件在 prop 变化时又 emit 回调」的组合，
回调里**必须先比对是否真有变化再回写**，否则回写必然制造新引用、形成自激振荡。

## 3.4 松手回弹（缩放后恢复原尺寸）

**现象**：拖手柄改尺寸，拖动中正常，松手立刻恢复。

**根因（两层）**：
1. `GridItem` 用**自己的 x/y/w/h props** 渲染（内部 `_e()` 仅在 resizing 期间覆盖），松手后回落 props；props 来自 store，而 store 要等 `layout-updated → 保存 → 回流`，回写前 props 一直是旧值；
2. 库在父组件里**原地修改** `:layout` 数组（`F.w = U`），不产生新引用 → 父 `watch(:layout)` 不触发 → 不 emit → 子项 `_e()` 不执行 → 内部几何仍是旧值。

**修复**：
- 几何由**本地 ref 持有**（`layoutRef`），库原地修改即等于更新 props → 松手不回弹；
- `onLayoutUpdated` 末尾 `layoutRef.value = next.map((i) => ({ ...i }))`，用新引用强制触发同步链路；
- store 仅作持久化目标，且**值相同就不替换数组**（prop 引用不变 → 不再二次 emit）。

## 3.5 别把 `undefined` 传给 CardHost（整块渲染失败）

**现象**：卡片建了但画布一张不显示。

**根因**：改成 `v-for="item in layoutRef"` + `<card-host :card="cardOf(item.i)!" />`，
非空断言 `!` 只是编译期语法，取不到卡片就传 `undefined` 进 **不在错误边界内**的 CardHost → 整块渲染失败。

**修复**：`v-for="card in dashboardStore.cards"` + `<card-host :card="card" />`；
几何经 `geoMap/geoOf()` **查询表**取本地真源（取不到回落 store 布局），**不用非空断言**；
`v-if` 改为 `dashboardStore.cards.length > 0`。

## 3.6 ⭐ 滚动容器"假不溢出"：flex 子项被压扁（配置抽屉不能滚动）

**现象**：配置抽屉内容超出高度，但**滚不动**，「实时预览」总被截一截。
已经给容器加了 `overflow-y: auto` 也没用。

**根因（CSS 规范陷阱）**：`.ma-drawer__body` 是 flex 列容器，其子项 `.ma-drawer__preview` 设了 `overflow: hidden`。
按规范，**`overflow` 非 `visible` 的 flex 子项，自动最小尺寸（`min-height: auto`）解析为 0**
（普通子项有 min-content 保护，它没有，可被无限压扁）。
内容超高时 flex 收缩阶段**先把预览框压扁**来消化溢出 → 容器恰好"装得下" →
`scrollHeight === clientHeight` → `overflow-y: auto` **永不出现滚动条**。

**修复（一行）**：
```css
.ma-drawer__body > * { flex-shrink: 0; }
```
子项一律不收缩，溢出真实发生，滚动条才会出现。

**⭐ 教训**：滚动容器若是 flex 列布局，**必须同时禁用子项收缩**（或给子项显式 min-height）。
排查"不能滚动"先分两类：
- **容器高度没约束**（整页被内容撑高）→ 看容器外层页脚是否被顶出视口；
- **容器内子项被压扁**（假不溢出）→ 看子项实际尺寸是否被压缩。

## 3.7 界面"整体跳一下"：文档流里的条件渲染 + 滚动条槽位

**现象**：偶尔整个界面突然位移一下。

**根因（两处叠加）**：
1. `ConnectionBanner.vue` 用 `v-if` 渲染，**26px 高、处在正常文档流**（`.ma-view` flex 列中 TopBar 之下）。
   WS 抖动 → `connPhase` 变 reconnecting → 这 26px 凭空出现，**把整个画布顶下去**，恢复时弹回；
2. 放大器：`.ma-canvas { overflow-y: auto }`，画布少 26px → 滚动条出现/消失 → 可用宽度变化 →
   grid 重算列宽 → **所有卡片重排**，位移被放大。

**修复**：
```css
/* 1. 横幅改为悬浮：外层加定位容器 .ma-view__body{position:relative} */
.ma-banner { position: absolute; top: 0; left: 0; right: 0; z-index: 60; }

/* 2. 锁定滚动条槽位，消除宽度抖动 */
.ma-canvas { scrollbar-gutter: stable; }
```

**修复前先排除**：卡片重连遮罩（`position:absolute`，不占位）、naive-ui 通知（固定定位）、
侧栏宽度（固定常量不可折叠）——这些都不产生位移。

## 3.8 视频卡死锁：`sourceOnDemand` 与"等帧才挂载"互斥

**现象**：视频卡永远显示「未收到数据」。

**根因**：MediaMTX 路径注册时带 `sourceOnDemand: true`（**有人读才拉上游流**，日志实证：
有读者 → 拉流 → 无读者 10s 后 `stopped: not needed by anyone`）。
而 `CardHost` 用 `hasFrames` 门控渲染器，且 `waiting` 分支优先 → 卡片永不挂载 → 没有读者 →
路径永不就绪 → 永远没有帧 → **死锁**。

**修复**：`CardHost` 新增 `needsFrames = card.rendererType !== 'video'`，
loading/waiting 分支与渲染器门控都受其约束，**视频卡挂载即渲染**，由它自己发起 WHEP/HLS 请求成为读者。

## 3.9 静默失败必须留出口

**现象**：看板加载失败时界面一片空白，用户无从判断。

**根因**：`dashboardStore.error` 无 UI 出口，未捕获异常只进 console。

**修复**：
1. `main.ts` 全局 `error` / `unhandledrejection` 监听 → 同时 `console.error` 与 `uiStore.error`；
2. `DashboardCanvas.vue` 空状态时显示 `dashboardStore.error`；
3. （临时）画布右上角诊断角标：`[诊断] 看板=… · 卡片=N张 · 加载中=… · 错误=… || DOM: 容器=… 项数=…`。

**判读**：`卡片=N张` 但 `DOM 项数=0` → 渲染层问题（如 3.1）；
`channels=0` → CardHost 未挂载。两者结合可秒定位。
