# 04 高德地图（样式 / 图层 / 密钥 / 坐标系）

> 地图相关的坑几乎全是**静默失败**：不报错、底图照常显示，只是样式/定位不对。务必按顺序排查。

## 4.1 三个配置项（`server/config.yaml` 的 `web` 段）

```yaml
web:
  amapKey: "你的高德 Key"
  amapSecurityCode: "与 Key 配对的安全密钥 securityJsCode"
  amapForceWebGL: true
```

| 配置项 | 作用 | 缺失后果 |
|---|---|---|
| `amapKey` | 高德 JS API Key | 地图卡降级为「配置指引 + 坐标列表」，**不会**换境外底图（合规硬约束） |
| `amapSecurityCode` | 2021-12-02 之后申请的 Key 必须配对（控制台与 Key 同页展示） | 样式服务静默失败：底图正常，但**切暗色等样式无反应** |
| `amapForceWebGL` | 关闭 WebGL 性能保护、强制启用 WebGL 绘制 | 无 GPU / 软件渲染 / 部分手机 WebView 下高德报"浏览器版本过低"且**不渲染样式** |

**安全密钥必须在 JSAPI 脚本加载之前**挂上（官方 Loader 要求）：

```ts
window._AMapSecurityConfig = { securityJsCode: code }   // loader.load() 之前
```

## 4.2 ⭐ 底图样式切换不生效：按顺序排查四步

| 步骤 | 排查项 | 说明 |
|---|---|---|
| ① | **样式值是否合法** | 官方内置样式只有：`normal` / `dark` / `light` / `whitesmoke` / `fresh` / `grey` / `graffiti` / `macaron` / `blue` / `darkblue` / `wine`。**`satellite` 不是 mapStyle**，传它会被静默忽略、回落标准样式 |
| ② | 是否配了 `amapSecurityCode` | 见上表 |
| ③ | 是否启用 WebGL | 见上表；控制台出现"浏览器版本过低"基本就是它（**注意：这是误导性文案，浏览器可能很新**） |
| ④ | 区分「没调用」还是「没渲染」 | 控制台执行 `__maMap.getMapStyle()`：返回目标样式值 → 前端已调用成功、是高德侧没画出来；`undefined` → 前端没走到 |

### 真实案例（三步才定位）

1. 初判：以为是没调 `setMapStyle` → 加了 watcher，**依旧无效**；
2. 查官方文档发现 `satellite` 不在样式列表 → 用户"看到卫星"其实是标准底图被误认 → 卫星改为图层实现（见 4.3）；
3. 用户控制台出现 `浏览器版本过低` + `getMapStyle()` 返回 `amap://styles/dark`（说明调用成功）→
   定位到 **WebGL 未启用**：JSAPI 默认以 `failIfMajorPerformanceCaveat` 取 WebGL 上下文，
   无 GPU / 软件渲染 / 手机 WebView 被判"性能不足"→ 不启用 WebGL → 样式引擎不工作。
   **解法**：脚本加载前置 `window.forceWebGL = true`（2.0 增强版再加 `forceWebGLBaseRender = true`）。

> 卫星能切、暗色不能切，正是这个症状的典型特征：**卫星是纯瓦片图层，不走样式引擎**。

## 4.3 卫星图必须用图层实现，不是样式

```ts
// ❌ 无效：satellite 不在官方样式列表
map.setMapStyle('amap://styles/satellite')

// ✅ 正确：官方卫星瓦片图层
const layer = new AMap.TileLayer.Satellite()
map.add(layer)      // 切换走时 map.remove(layer)
```

注意：卫星是**叠加在底图上的图层**，切换走时必须 `map.remove`，否则会盖住暗色底图，
表现为"切到暗色但画面还是卫星"。

## 4.4 坐标系（选错会有几百米偏移）

- 数据在前端用 `gcoord` **离线**转换（WGS-84 → GCJ-02），**后端只盖章 `crs`、绝不改坐标值**（合规硬约束）。
- 卡片里「输入坐标系（请确认）」决定换算方式：

| 选项 | 适用 |
|---|---|
| **WGS-84** | GPS 原始、ROS `NavSatFix` —— **默认先选这个** |
| GCJ-02 | 已转换过的高德/腾讯坐标 |
| BD-09 | 百度坐标（在 GCJ-02 上再叠一层偏移） |

**排查**：点位系统性偏几百米 → 多半是坐标系选错（曾遇到选成 `BD-09` 导致偏移）。
先 WGS-84，偏了再试 GCJ-02。

## 4.5 JSON / HTTP 通道的字段路径

**两个坑（曾导致地图 0 个点）**：

1. **`root` 包装**：JSON 通道的载荷是 `model.JSONPayload{Root any}`，即 `frame.payload = { root: 原始响应 }`
   （`server/internal/model/payload.go:90`）。字段路径必须带 `root.` 前缀，但 UI 不提示，必踩。
   → 前端已自动补：`MapRenderer.firstNumberAt` 对每个候选路径都会再试 `root.` 前缀，
   **填 `data.pose.latitude` 或 `root.data.pose.latitude` 都可以**。
2. **分隔符**：路径解析原本只按 `.` 切分，填 `data/pose/latitude` 会静默取空。
   → 已改为 `split(/[./]/)`，**点分与斜杠均可**。

**留空时的默认候选**：`latitude/lat/gps.lat/pose.position.lat`（经度同理）。
自定义结构（如 `data.pose.latitude`）必须显式填。

---

## 4.6 ROS 通道不需要配字段路径

`sensor_msgs/NavSatFix` 会被后端 `BuildGeoPose` 直接归一化成 `geo_pose` 帧，
地图卡**只需设输入坐标系**，不必填 latPath/lonPath —— 与 JSON/HTTP 通道不同，别照抄。

---

## 4.7 合规红线（不可动摇）

1. 底图**仅**用高德 JS API，禁止 Google Maps / 未审校 OSM 等境外底图；
2. 未配置 Key 时降级为「坐标列表」，**绝不切换到任何境外底图**；
3. 坐标系 GCJ-02，转换在前端离线完成；
4. 界面显式声明输入坐标系（卡片 HUD / 脚注）。
