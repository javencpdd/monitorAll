# 01 环境与构建

## 1.1 `/tmp` 太小导致 Go 构建失败

**现象**：`make build` 报 `no space left on device`。

**根因**：该环境 `/tmp` 只有 10M tmpfs，go build 的临时文件放不下。

**修复**：构建前指定临时目录：

```bash
export GOTMPDIR=/home/jack/.tmp
```

**教训**：任何 Go 构建命令前都带上它；CI/容器不受影响，但本机一定会踩。

---

## 1.2 Go 不在默认 PATH

**现象**：`go: command not found`。

**根因**：Go 1.22.5 装在 `/usr/local/go/bin`，未进 PATH。

**修复**：

```bash
export PATH=$PATH:/usr/local/go/bin
```

## 1.3 构建顺序（改了前端必须走完整三步）

前端产物通过 `go:embed` 打进后端二进制，**只编译后端不会带上新前端**：

```bash
cd web && npm run build                                   # 1. 构建前端
rm -rf ../server/internal/web/dist && cp -r dist ../server/internal/web/dist   # 2. 拷进 embed 目录
cd ../server && export GOTMPDIR=/home/jack/.tmp && make build   # 3. 编译单二进制
```

**验证改生效**（构建产物哈希是唯一凭据）：

```bash
curl --noproxy '*' -s http://127.0.0.1:8080/ | grep -oE 'assets/index-[A-Za-z0-9_-]+\.js'
ls -1 server/internal/web/dist/assets/index-*.js
# 两者必须一致，且等于最新构建产物
```

## 1.4 后台进程在工具调用结束后被回收

**现象**：`nohup`/`setsid` 起的服务，下次执行命令时已经不在了（端口空、`ps` 查不到）。

**根因**：本环境每次命令结束会回收进程组。

**修复**：
- 需要常驻做验证时，用后台任务方式启动（`run_in_background`），实测可存活 20+ 分钟；
- 长期运行请**在用户自己的终端**里 `./scripts/start-local.sh`。

**连带影响**：我这边看不到也杀不掉用户的进程（`pkill` 无效、`ps` 查不到），所以**每次改完都必须请用户自己重启**。

## 1.5 `http_proxy` 会劫持本地请求（反复踩）

**现象**：`curl http://127.0.0.1:8080/...` 返回 000 / 301 / `Name does not resolve`。

**根因**：环境设了 `http_proxy`，curl 把 127.0.0.1 也送进代理。

**修复**：所有本地 curl 一律加 `--noproxy '*'`（**引号不能省**，否则 `*` 被 shell 展开）：

```bash
curl --noproxy '*' -s http://127.0.0.1:8080/api/v1/dashboards
```

**同类坑**：
- 后端 Go 的 `websocket.Dialer` 用了 `Proxy: http.ProxyFromEnvironment` → 拨 rosbridge 也会走代理失败。启动前 `NO_PROXY=<机器人IP>` 或 `unset http_proxy https_proxy`。
- `deploy/start.sh` 的探活 curl 同样必须加。

## 1.6 本环境无法做浏览器自动化

**现象**：
- `google-chrome --headless=new` 启动即崩溃（SIGTRAP / core dump），根因 `crashpad ... ptrace: Operation not permitted`，加 `--no-sandbox --disable-dev-shm-usage --no-zygote --disable-breakpad` 均无效；
- `agent-browser`（基于 playwright）能启动，但 `open <url>` 持续超时、随后 `CDP response channel closed` 守护进程卡死。

**后果**：**前端交互类问题无法真机验证**，只能靠静态分析 + 构建产物核对 + 请用户验证。

**应对**：见 [06 调试方法论](./06-调试方法论.md)——用后端日志、REST 直查、Node WS 探针、产物 grep 四板斧取证。

## 1.7 其它环境细节

| 事项 | 说明 |
|---|---|
| `DefaultConfig()` 里 `TLSEnabled: true` | 单测里 `cfg.PublicScheme()` 得到 `https`；用户实际配置关 TLS → `http`。断言时别写死 |
| 沙箱写保护 | `deploy/data/` 目录 root 也 chmod 失败 → 配置文件必须放 `deploy/config.yaml` 再挂载进容器 |
| Node/Python | 优先用受管版本：Node `/home/jack/.workbuddy/binaries/node/versions/22.22.2/bin/node`；装包进 `~/.workbuddy/binaries/node/workspace`，**不要 `npm install -g`** |
| 校验 YAML | 本机没有 `pyyaml`；判断后端配置是否合法，直接看启动日志里的「配置加载完成」是否出现 |
