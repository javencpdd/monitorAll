## 1. 系统概述

### 1.1 它是什么

MonitorAll 是一个**局域网内的卡片式监控看板**：把三类异构数据源统一接入，用「可拖拽的卡片」自由编排成大屏。

| 能接入 | 说明 |
| --- | --- |
| **视频流** | RTMP 地址（如 `rtmp://172.31.68.227:1936/live/lite3`），经 MediaMTX 转封装为 WebRTC / HLS |
| **ROS 话题** | ROS1（Noetic/Melodic）与 ROS2（Humble/Foxy）双支持，经 rosbridge 订阅 |
| **HTTP 接口** | 定时轮询自建遥测服务，支持 JSONPath 提取字段 |

同一份数据可自由切换 **7 种渲染方式**：原始数据、表格、仪表、XY 折线图、图像、地图、视频播放器。

### 1.2 核心概念（理解这四个就够了）

```
看板 Dashboard
  └── 卡片 Card = 通道 Channel + 渲染器 Renderer + 渲染配置
                    ↑
              数据源 DataSource（一个连接：一条 RTMP / 一个 ROS Master / 一个 HTTP 服务）
```

| 概念 | 通俗解释 |
| --- | --- |
| **数据源** | 「连到哪儿」——一个 RTMP 地址、一个 rosbridge 地址、一个 HTTP 根地址 |
| **通道** | 「取哪一路数据」——某个 RTMP path、某个 ROS 话题、某个 HTTP 端点。**卡片绑定的是通道** |
| **卡片** | 「看板上的一格」——通道 + 渲染器 + 配置 |
| **看板** | 「一整块大屏」——一组卡片 + 布局 |

> 一个数据源可以有多个通道（如一个 ROS Master 下订阅 20 个话题），后端只建**一条连接**，多张卡片共享，不会重复连接。

### 1.3 界面结构

```
┌──────────────────────────────────────────────────────────────────┐
│ ① 顶栏  看板切换/新建/重命名/删除 │ 编辑模式 │ +新建卡片 │ 保存 │ 连接状态 │ 主题 │ ⛨证书 │
├────────────┬─────────────────────────────────────────────────────┤
│ ② 数据源面板│ ③ 网格画布（12 列栅格）                              │
│   搜索框    │   卡片区（拖拽 / 缩放）                              │
│   ▾ 视频源  │                                                     │
│   ▾ ROS     │                                                     │
│   ▾ HTTP    │                                                     │
│ [+新建数据源]│                                                     │
└────────────┴─────────────────────────────────────────────────────┘
                                         ④ 卡片配置抽屉（从右侧滑出）
```

## 2. 部署与启动

### 2.1 方式 A：Docker Compose（推荐）

前置：安装 Docker 与 Docker Compose 插件。

```bash
cd deploy
./start.sh          # 一键：构建镜像 + 启动 + 就绪检查 + 打印访问地址
./stop.sh           # 一键停止（保留数据）；./stop.sh -v 连数据一起清空（需确认）
```

`start.sh` 会自动完成：

1. 检查 Docker 可用性与 `config.yaml` 是否存在；
2. **比对 `config.yaml` 里的 `publicHost` 与宿主机真实 IP**，不匹配直接告警（这是视频不出画面的头号原因）；
3. 构建镜像并启动 `monitorall`（后端 + 前端）+ `mediamtx`（流媒体）；
4. 分别探活后端 `/healthz` 与 MediaMTX `:9997`；
5. 列出可用的访问地址。

启动成功后浏览器打开 `http://<宿主机IP>:8080`。

### 2.2 方式 B：本地裸跑

前置：Go 1.22+；构建前端还需要 Node 18+。

```bash
cd server
make build-web      # 构建前端产物并拷贝到 internal/web/dist（供 go:embed）
make build          # 编译单二进制 → server/bin/monitorall
./bin/monitorall --config ./config.yaml
```

裸跑时 MediaMTX 需**单独启动**（Docker 或二进制均可）：

```bash
docker run -d --name mediamtx --restart unless-stopped \
  -p 1936:1936 -p 8888:8888 -p 8889:8889 -p 9997:9997 \
  bluenviron/mediamtx:latest
```

> 裸跑时 `config.yaml` 的 `mediamtx.apiBase` 必须指向 MediaMTX 真实地址（本机为 `http://127.0.0.1:9997`），**不能**用 compose 服务名 `mediamtx`。

### 2.3 更新代码后怎么处理

| 改了什么 | 命令 | 原因 |
| --- | --- | --- |
| `web/**` 或 `server/**` **代码** | `./start.sh` | 代码在**镜像构建阶段**编译并 embed 进二进制，必须重建 |
| `deploy/config.yaml`、`mediamtx/mediamtx.yml` | `./start.sh --no-build` | 只读挂载文件，重启容器即重新加载，无需重建 |
| `deploy/docker-compose.yml` | `./start.sh` | 编排变了，需重新创建容器 |

> **两个坑**：
> ① 只改配置时直接 `docker compose up -d` —— 对已运行容器**不会重启**，配置改动不生效；请用 `--no-build`（内部执行 `restart`）。
> ② 改了前端却只重启不重建 —— 界面会停留在旧版本。**碰了 `web/` 或 `server/` 就一定要重建。**

## 3. 首次配置（必做）

### 3.1 设置宿主机 IP（最关键）

编辑 `deploy/config.yaml`（裸跑则改 `server/config.yaml`），把两处改成**你浏览器访问看板所用的局域网 IP**：

```yaml
server:
  lanHost: "10.42.0.1"        # ← 改成你的宿主机 IP
mediamtx:
  publicHost: "10.42.0.1"     # ← 同上
```

查 IP：`hostname -I`

**为什么必须配**：前端拿到的视频播放地址，host 取自 `publicHost → lanHost → 127.0.0.1`。若两者都留空，会退化成 `127.0.0.1`（对浏览器无意义）或容器内网 IP（浏览器不可达），表现就是卡片一直「协商超时 / Failed to fetch」。

### 3.2 高德地图 Key（需要地图卡片时）

```yaml
web:
  amapKey: "你的高德 JS API Key"
```

未配置时，地图卡片显示配置指引 + 纯坐标列表，**不会**降级到境外底图（合规约束）。

### 3.3 视频链路前置：MediaMTX

视频要能播放，MediaMTX 必须满足：

1. **容器/进程在运行**：`docker compose ps` 里 `mediamtx` 状态为 `running`。
2. **控制 API 已开启**：`mediamtx.yml` 里必须有 `api: yes`。后端靠它去**编排拉流**；若为 `no`，MediaMTX 永远拉不到流，日志会报 `no stream is available on path 'live/lite3'`。
3. **端口规划**（与 compose 一致）：

| 端口 | 用途 |
| --- | --- |
| 1936 | RTMP 入（`rtmpAddress: :1936`） |
| 8888 | HLS 播放（降级路径） |
| 8889 | WebRTC / WHEP（首选，亚秒级） |
| 9997 | HTTP 控制 API（后端调用，仅局域网） |

验证 MediaMTX 是否拉到了流：

```bash
curl http://127.0.0.1:9997/v3/paths/list
# 看到 live/lite3 且 "ready": true 即成功
```

## 4. 接入数据源

入口：左侧面板底部 **「+ 新建数据源」**。向导为两步：**① 选类型 → ② 填参数（可先「测试连接」）**。

### 4.1 视频流（RTMP）

**Step 1** 选「视频流（RTMP）」。

**Step 2** 填写：

| 字段 | 说明 |
| --- | --- |
| 名称 | 显示名，如 `lite3 相机` |
| RTMP 地址 | 完整地址，如 `rtmp://172.31.68.227:1936/live/lite3`（格式实时校验，非法会红字） |
| 首选协议 | `WebRTC`（≤0.5s，需 HTTPS）/ `HLS`（2–3s，HTTP 下可用）/ `HTTP-FLV`（需外部 FLV 网关） |
| 携带音频 | 是否请求音轨 |

建议点 **「测试连接」**，成功会显示识别到的通道。

> **RTMP 地址的语义**：它是要监控的**流的地址**。若该地址不在本机（如 `172.31.68.227`），后端会让 MediaMTX 以「拉流」方式去拉；若推给本机 MediaMTX（host 为 127.0.0.1/本机 IP 且端口一致），则走「收流」方式。
> **path 必须与实际推流一致**（`live/lite3` 的大小写、斜杠都要对），否则会出现「数据源在线但画面一直转圈」。

### 4.2 ROS 话题（ROS1 / ROS2）

**前置**：目标机器需运行 rosbridge：

```bash
# ROS1 (Noetic/Melodic)
sudo apt install ros-noetic-rosbridge-suite
roslaunch rosbridge_server rosbridge_websocket.launch      # 默认 ws://<host>:9090

# ROS2 (Humble/Foxy)
sudo apt install ros-humble-rosbridge-suite
ros2 launch rosbridge_server rosbridge_websocket_launch.xml
```

**Step 2** 填写：

| 字段 | 说明 |
| --- | --- |
| ROS 版本 | 下拉切换 ROS1 / ROS2（切换后表单字段不变） |
| rosbridge 地址 | 如 `ws://172.31.68.227:9090` |
| Domain ID | 仅 ROS2 需要 |
| 话题列表 | 一行一个（或用逗号分隔），如 `/odom`、`/imu/data`、`/battery` |

> MVP 以**手工填写话题**为主路径（ROS2 各发行版 rosapi 服务名不一致，自动发现为软增强，失败时静默降级）。

**话题类型 → 渲染器推荐**（系统会自动过滤候选）：

| ROS 消息类型 | 归一化类型 | 推荐渲染器 |
| --- | --- | --- |
| `Float32/64`、`Int32`、`Bool`、`BatteryState` | `scalar` | 仪表 / 原始数据 |
| `Imu`、`Odometry` | `time_series_sample` | XY 折线图 |
| `NavSatFix` | `geo_pose` | 地图 |
| `Image` / `CompressedImage` | `image` | 图像 |
| 其它未知类型 | `json` | 原始数据 |

### 4.3 HTTP 轮询接口

| 字段 | 说明 |
| --- | --- |
| 接口地址 | 如 `http://172.31.68.9:8080/api/stat` |
| 方法 | GET / POST |
| 轮询间隔(ms) | 默认 1000，下限 100 |
| JSONPath | 留空则取整个响应；如 `data.items` |
| 超时(ms) | 默认 3000 |
| 请求体 | 仅 POST 时填写 |

> 轮询在**后端**进行，可规避浏览器跨域（CORS）问题。

### 4.4 数据源与通道管理

- **搜索**：面板顶部搜索框可按数据源名/协议/通道名过滤。
- **折叠**：点数据源前的 `▾ / ▸`。
- **删除数据源**：hover 数据源行 → 点 `✕`（其下通道与引用它们的卡片会一并清理，有二次确认）。
- **管理通道**：点某数据源下的「管理通道」→ 出现 `✕` → 删除单个通道。
- **拖拽建档**：**通道可直接拖到画布**，会直接打开「新建卡片」抽屉并预选该通道。

## 5. 编排看板

### 5.1 编辑模式 / 查看模式

点顶栏「**编辑模式**」切换（快捷键 `E`）。

| 模式 | 行为 |
| --- | --- |
| **编辑模式** | 可拖拽/缩放卡片、显示卡片操作按钮（⚙ 配置、✕ 删除）、可新建卡片 |
| **查看模式** | 锁定布局，禁止拖动与缩放（防止值班同事误操作） |

### 5.2 新建卡片（三步向导）

方式一：顶栏「**+ 新建卡片**」。
方式二：**从左侧面板把通道拖到画布**（自动跳过第 1 步）。

| 步骤 | 操作 |
| --- | --- |
| **① 选择通道** | 从列表选一个通道（选中后会自动拉取「样例帧」识别数据类型） |
| **② 选择渲染器** | 系统**只列出与该数据类型兼容的渲染器**，兼容项打「推荐」标签 |
| **③ 配置** | 填写标题、单位、显示脚注、小数位，以及渲染器专属配置（右侧实时预览） |

点「**添加到看板**」完成。

> 若样例帧提示「3 秒内未收到数据」，说明该通道暂时没有数据流入，可先按通道声明类型选渲染器，或先解决数据源在线问题。

### 5.3 拖拽与缩放

**仅在编辑模式下生效。**

- **移动**：按住卡片空白处拖动，松手自动吸附到网格。
- **缩放**：鼠标移到卡片**右下角**出现斜纹手柄（光标变为 `↘`），拖动即可改变宽高。
- **约束**：最小 2×2 格，不可拖出画布；12 列栅格。

> 卡片有最小尺寸限制；若某卡片缩到最小后无法再缩，属正常约束。

### 5.4 编辑 / 删除卡片

编辑模式 → 卡片右上角：

- **⚙**：打开配置抽屉，可改标题/单位/渲染器/配置（切换渲染器时会保留可复用的配置项）。
- **✕**：删除卡片（二次确认）。

### 5.5 保存与快捷键

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl + S` | 保存看板 |
| `E` | 切换编辑 / 查看模式 |
| `Esc` | 关闭抽屉 / 退出编辑 |

- 有未保存改动时，顶栏「保存」按钮旁会出现**橙色圆点**。
- 拖拽/缩放布局会**立即自动落库**（轻量保存）。
- 关闭页面前若有未保存改动，浏览器会提示确认。

> 保存采用乐观锁：若看板在别处被改过，会提示「看板已被修改，请刷新后重试」，**不做自动合并**。

### 5.6 多看板管理

顶栏左侧下拉旁：

- **切换**：下拉选择看板（URL 变为 `/dashboard/<id>`，刷新后仍停留当前看板）。
- **新建** / **重命名** / **删除**（删除不可恢复，有二次确认）。
- 首次启动会自动创建「**默认看板**」。

## 6. 渲染器参考

### 6.1 总览

| 渲染器 | 接受的数据类型 | 典型用途 |
| --- | --- | --- |
| **原始数据**（json-tree） | 任意类型（兜底） | 调试、看完整 JSON |
| **表格**（table） | table / json / time_series_sample | 行列数据、自动拍平对象 |
| **仪表**（gauge） | scalar / json / time_series_sample | 电压、温度、速度 |
| **XY 折线图**（line-chart） | time_series_sample / scalar / json | 里程计、IMU 时序 |
| **图像**（image） | image | ROS 相机画面 |
| **地图**（map） | geo_pose / json | GPS 轨迹、机器人位姿（GCJ-02） |
| **视频播放器**（video） | video_stream | RTMP 转封装后的直播画面 |

### 6.2 各渲染器配置项

**仪表（gauge）**
`值字段`（点选）、`量程下限/上限`、`小数位`、`阈值区段`（红黄绿分段着色）、`显示指针`、`脚注显示 MIN/MAX`

**XY 折线图（line-chart）**
`字段`（多选，最多 8 条）、`时间窗口`（默认 60s）、`Y 轴下限/上限`、`图例开关`；支持暂停 / 清空 / 导出 CSV

**地图（map，GCJ-02）**
`底图样式`、`输入坐标系`（WGS-84 / GCJ-02）、`轨迹尾迹点数`（默认 200）、`镜头跟随当前点`、`朝向箭头随 yaw 旋转`、`初始缩放级别`

> **坐标系**：机器人 GPS / ROS 常输出 **WGS-84**，高德底图是 **GCJ-02**。系统在前端用离线算法自动转换，并在卡片脚注显示当前生效坐标系。请务必在配置里**如实声明输入坐标系**，否则会有数百米偏移。转换后坐标不会被改写落库。

**原始数据（json-tree）**
`默认展开层级`、`显示类型标注`、`最大节点数`（超出截断，防卡死）

**表格（table）**
`显示列`（留空=自动）、`最大行数`、`允许排序`、`冻结首列`

**图像（image）**
`缩放模式`、`显示时间戳水印`、`最大帧率`（默认 10Hz，降低 CPU 与带宽）

**视频播放器（video）**
`首选协议`、`自动播放`、`静音启动`、`悬浮控制条`、`自动降级`、`重试首选协议间隔`；支持卡片内全屏、手动强制切换协议

## 7. 状态与提示

### 7.1 四态角标

| 颜色 | 状态 | 含义 |
| --- | --- | --- |
| 🟢 绿 | 在线 | 数据正常流入 |
| ⚪ 灰 | 离线 | 数据源未启用或已断开 |
| 🟡 黄（闪） | 重连中 | 断线自动重连中（指数退避，1s→30s） |
| 🔴 红 | 错误 | 订阅失败，hover 可看 `lastError` |

### 7.2 卡片三态

| 场景 | 卡片表现 |
| --- | --- |
| 等待首帧（<3s） | 骨架屏 |
| 长时间无数据 | 「未收到数据」，提示检查话题名/数据源 |
| 未配置 | 「选择数据开始」+ 配置按钮 |
| 连接中断 | 灰化遮罩 + 重连倒计时 |
| 渲染异常 | 错误卡（**不影响其它卡片**）+ 重试按钮 |

### 7.3 顶栏连接状态

`后端在线 xx ms`（ws 延迟）/ `正在连接后端…` / `重连中…` / `后端离线`。后端重启后前端会自动重连并恢复全部订阅，无需刷新。

## 8. 常见问题排查（FAQ）

### Q1. 视频卡片一直「HLS 协商超时」或「Failed to fetch」

按顺序排查：

```bash
# ① MediaMTX 是否在跑？（必须 running）
docker compose ps

# ② MediaMTX 是否拉到了流？（必须看到 live/lite3 且 ready:true）
curl http://127.0.0.1:9997/v3/paths/list

# ③ 源本身是否可拉？（能列出 H264 流即正常）
ffprobe -v error -show_streams rtmp://172.31.68.227:1936/live/lite3
```

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `9997` connection refused / 8888 返回 502 | **MediaMTX 容器没起来** | `docker compose logs mediamtx --tail 50` 看原因；确认镜像可拉取 |
| `no stream is available on path 'xxx'` | MediaMTX 上无此流 | 检查 `mediamtx.yml` 是否 `api: yes`（否则后端无法编排拉流） |
| `Failed to fetch` | 前端拿到的地址不可达 | **检查 `publicHost`/`lanHost` 是否等于你访问看板用的宿主机 IP** |
| 卡片「数据源在线但一直转圈」 | RTMP path 与推流 path 不一致 | 核对 path 大小写与斜杠 |

### Q2. 卡片无法拖拽缩放

- 确认处于**编辑模式**（顶栏显示「◉ 编辑中」）。
- 缩放要拖卡片**右下角手柄**（hover 才显示）。
- 若确实失效，多为前端产物未更新：改过 `web/` 后必须 `./start.sh` **重建**，并强刷浏览器（`Ctrl+Shift+R`）。

### Q3. 地图卡片空白 / 提示配置

- 未配置 `web.amapKey`：按卡片提示去申请高德 JS API Key 并填入配置。
- 有 Key 但无点位：确认数据源输出 `geo_pose`（如 `NavSatFix`），且**输入坐标系**声明正确。

### Q4. 图像卡片不刷新

- 检查 ROS 图像话题是否在推流；图像通道默认限流 **10Hz**、rosbridge 侧启用 JPEG 压缩。
- 可在渲染器配置里调整「最大帧率」。

### Q5. 顶栏显示「后端离线」

```bash
curl http://127.0.0.1:8080/healthz     # 期望 {"ok":true,...}
docker compose logs monitorall --tail 50
```

### Q6. 改了配置但不生效

`docker compose up -d` 对**已运行**容器不会重启，配置不会重新加载。请用：

```bash
./start.sh --no-build        # 内部执行 restart，重新加载挂载的配置文件
```

### Q7. HTTPS 访问浏览器告警 / WebRTC 不可用

- 当前推荐部署为**纯 HTTP**（`tlsEnabled: false`），此时 WebRTC 受浏览器安全上下文限制，视频自动降级 HLS（1–3s）。
- 需要亚秒级 WebRTC：开启 `tlsEnabled: true`，浏览器访问 `https://<IP>:8443`，先访问 `/trust` 按指引信任自签证书，再把卡片首选协议设为 WebRTC。

## 10. 附录

### 10.1 配置文件要点

```yaml
server:
  httpAddr: ":8080"
  tlsEnabled: false          # 纯 HTTP 部署（推荐先用这个跑通）
  lanHost: "10.42.0.1"       # ★ 必配：宿主机 IP

mediamtx:
  mode: embedded             # embedded=本机托管 / external=外部已部署
  apiBase: "http://mediamtx:9997"   # Docker 用服务名；裸跑用 http://127.0.0.1:9997
  publicHost: "10.42.0.1"    # ★ 必配：浏览器直连 MediaMTX 的 host
  publicScheme: "http"       # 与 tlsEnabled 保持一致
  encryption: "never"        # 纯 HTTP 下不加密

web:
  amapKey: ""                # 地图卡片需要
```
